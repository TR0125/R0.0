# 架构与设计

状态：`active`

## 1. 架构总览

当前系统是“任务型控制”架构，不走高频 `cmd_vel`：

1. 总控通过 `/chassis/command` 下发统一命令
2. 桥接节点将命令转为机器人 HTTP 协议请求
3. 机器人通过 HTTP 回调上报状态到香橙派
4. 网关将回调原文转发到 `/protocol/*`
5. 位姿桥将 `pose_msg` 转换为 `/raybot/base_pose`

---

## 2. 关键节点与职责

- `protocol_gateway`：接收机器人回调，转发 `/protocol/*`
- `protocol_command_bridge`：消费 `ChassisCommand`，调用协议动作层
- `robot_status_pose_bridge`：把 `pose_msg` 标准化为 `PoseStamped`
- `protocol_actions` / `protocol_mission`：HTTP 协议封装
- `protocol_client`：HTTP 请求统一入口

---

## 3. 关键数据流

### 3.1 命令流

`/chassis/command` -> `protocol_command_bridge` -> `protocol_actions` -> 机器人 HTTP API

### 3.2 状态流

机器人回调 -> `protocol_gateway` -> `/protocol/robot_status` 等 Topic

### 3.3 位姿流（新增）

`/protocol/robot_status.pose_msg` -> `robot_status_pose_bridge` -> `/raybot/base_pose`

转换规则（默认）：

- `px/py`：mm -> m（`position_scale=0.001`）
- `pt`：deg -> quaternion（`yaw_is_degree=true`）

---

## 4. 设计边界

- 支持任务型动作：`move/head/goto/charge/stop` 等
- 不提供 `/cmd_vel` 速度流控制
- 网关默认透传 JSON，不做业务字段改写
- 任务状态字段以 `task_cmd` 为准
