>

## 1. 联调前检查

现场默认参数：

- 机器人控制地址：`http://192.168.1.55:8283`
- 香橙派回调地址：`http://192.168.1.25:8283`
- `robot_id`：`ubot-001`

联调前确认：

- 机器人与香橙派网络互通
- 机器人 HTTP 服务可访问
- 香橙派可监听 `8283`
- 当前地图与目标点名称已确认
- 每个新开的终端都要重新 `source /opt/ros/humble/setup.bash` 和 `source install/setup.bash`

编译：

```bash
cd /home/raybot/raybot_chassis_ws
source /opt/ros/humble/setup.bash
colcon build --packages-select raybot_chassis_msgs raybot_chassis_master chassis_move
source install/setup.bash
```

## 2. 启动协议回调网关

```bash
cd /home/raybot/raybot_chassis_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch chassis_move protocol_bringup.launch.py
```

网关启动后负责接收：

- `/robot/status`
- `/robot/mission/state`
- `/robot/mission/task/state`

查看状态回调：

```bash
ros2 topic echo /protocol/robot_status --full-length
```

查看任务回调：

```bash
ros2 topic echo /protocol/mission_state --full-length
```

```bash
ros2 topic echo /protocol/task_state --full-length
```

## 3. 使用协议 CLI 控制

建议先设置默认环境变量：

```bash
export TESTMOVE_BASE_URL=http://192.168.1.55:8283
export TESTMOVE_ROBOT_ID=ubot-001
export TESTMOVE_TIMEOUT_SEC=5
```

### 3.1 切换模式

```bash
ros2 run chassis_move protocol_cli -- set-mode AUTOMATIC
```

### 3.2 常用命令

前进：

```bash
ros2 run chassis_move protocol_cli -- move --distance-mm 300 --speed-mm-s 150
```

后退：

```bash
ros2 run chassis_move protocol_cli -- move --distance-mm -300 --speed-mm-s 150
```

左转：

```bash
ros2 run chassis_move protocol_cli -- head --angle-deg 20 --speed-deg-s 40
```

右转：

```bash
ros2 run chassis_move protocol_cli -- head --angle-deg -20 --speed-deg-s 40
```

停止：

```bash
ros2 run chassis_move protocol_cli -- stop
```

请求持续上报状态：

```bash
ros2 run chassis_move protocol_cli -- request-status path --report-duration-sec 300
```

到命名目标点：

```bash
ros2 run chassis_move protocol_cli -- goto-goal --goal A
```

到绝对位姿：

```bash
ros2 run chassis_move protocol_cli -- goto-pose --x-mm 3000 --y-mm 1000 --th-deg 90
```

回家：

```bash
ros2 run chassis_move protocol_cli -- go-home --goal Home
```

自动充电：

```bash
ros2 run chassis_move protocol_cli -- auto-charge
```

巡逻往返：

```bash
ros2 run chassis_move protocol_cli -- patrol-goals --from-goal B --to-goal A
```

说明：

- `patrol-goals` 当前执行流程是“到目标点 -> 等待 -> 返回起点”
- 如需取消任务，请使用 `cancel-mission`

取消任务：

```bash
ros2 run chassis_move protocol_cli -- \
  cancel-mission --mission-id manualgotogoal-001 --mission-name ManualGotoGoal
```

## 4. 使用总控单 Topic 控制

启动桥接节点：

```bash
cd /home/raybot/raybot_chassis_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch chassis_move protocol_command_bridge.launch.py
```

桥接节点启动成功后，建议先自检：

```bash
ros2 node list
```

```bash
ros2 topic info /chassis/command -v
```

期望结果：

- `ros2 node list` 中能看到 `/protocol_command_bridge`
- `/chassis/command` 存在
- `/chassis/command` 下至少有一个 subscriber
- `/chassis/command` 的类型是 `raybot_chassis_msgs/msg/ChassisCommand`
如果 `/chassis/command` 不存在，说明桥接节点没有真正启动成功，或当前终端没有 `source` 到这套工作区。

默认参数：

- `robot_base_url=http://192.168.1.55:8283`
- `robot_id=ubot-001`
- `legacy_command_topic=/chassis/command_legacy`

接口：

- 输入：`/chassis/command`
- legacy 输入：`/chassis/command_legacy`
- 输出：`/chassis/command_result`

### 4.1 命令格式

推荐消息类型为 `raybot_chassis_msgs/msg/ChassisCommand`。

兼容说明：

- `/chassis/command`：`raybot_chassis_msgs/msg/ChassisCommand`
- `/chassis/command_legacy`：`std_msgs/String`，其中 `data` 为 JSON

必填字段：

- `command_type`

推荐通过本地总控包发命令：

切模式：

```bash
ros2 topic pub --once /chassis/command raybot_chassis_msgs/msg/ChassisCommand \
  "{command_type: SET_MODE, operation_mode: AUTOMATIC}"
```

前进：

```bash
ros2 run raybot_chassis_master chassis_master_cli -- \
  move --distance-mm 300 --speed-mm-s 150
```

旋转：

```bash
ros2 run raybot_chassis_master chassis_master_cli -- \
  rotate --angle-deg 20 --speed-deg-s 40
```

到目标点：

```bash
ros2 run raybot_chassis_master chassis_master_cli -- goto-goal --goal A
```

AB 点往返：

```bash
ros2 run raybot_chassis_master chassis_master_cli -- \
  patrol-goals --from-goal B --to-goal A --wait-at-goal-sec 10
```

停止：

```bash
ros2 topic pub --once /chassis/command raybot_chassis_msgs/msg/ChassisCommand \
  "{command_type: STOP}"
```

legacy `topic pub` 示例：

```bash
ros2 topic pub --once /chassis/command_legacy std_msgs/msg/String \
  "{data: '{\"command_type\":\"GOTO_GOAL\",\"goal\":\"A\"}'}"
```

### 4.2 结果查看

```bash
ros2 topic echo /chassis/command_result
```

推荐在发命令前先打开这个窗口。

返回 JSON 中常见字段：

- `ok`
- `command_type`
- `robot_id`
- `request`
- `response`
- `error`

mission 型命令默认会自动补齐：

- `mission_name`
- `mission_id`

例如：

- 第一次 `GOTO_GOAL A`：`GotoGoalA` / `goto-a-001`
- 第二次 `GOTO_GOAL A`：`GotoGoalA` / `goto-a-002`
- 第一次 `PATROL_GOALS B->A`：`PatrolBToA` / `patrol-b-to-a-001`

说明：

- 上面的命名规则只适用于 `/chassis/command` 桥接节点
- `protocol_cli` 自身仍沿用 `ManualMove`、`ManualHead`、`ManualGotoGoal` 这一组默认任务名
- `protocol_cli` 若不显式传 `--mission-id`，会由 `protocol_mission.py` 自动生成时间戳型任务号

### 4.3 常见发送前自检

在使用 `raybot_chassis_master` 或 `ros2 topic pub` 发送命令前，建议先确认：

```bash
ros2 node list
```

```bash
ros2 topic info /chassis/command -v
```

```bash
ros2 topic echo /chassis/command_result
```

如果执行 `ros2 topic pub --once /chassis/command ...` 时看到：

```text
Waiting for at least 1 matching subscription(s)...
```

说明当前没有节点在订阅 `/chassis/command`。

优先排查：

- `protocol_command_bridge` 是否已经启动
- 当前终端是否已经 `source /opt/ros/humble/setup.bash`
- 当前终端是否已经 `source /home/raybot/raybot_chassis_ws/install/setup.bash`
- 运行中的桥接节点是否是这套最新工作区启动的

如果只是想先验证旧链路，可以改发 legacy 入口：

```bash
ros2 topic pub --once /chassis/command_legacy std_msgs/msg/String \
  "{data: '{\"command_type\":\"SET_MODE\",\"operation_mode\":\"AUTOMATIC\"}'}"
```

## 5. 键盘手操（保留）

```bash
cd /home/raybot/raybot_chassis_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run chassis_move protocol_teleop --ros-args \
  -p robot_base_url:=http://192.168.1.55:8283 \
  -p robot_id:=ubot-001
```

按键：

- `w/s`：前后移动
- `q/e`：原地旋转
- `a/d`：基于最新位姿做侧移
- `space`：停止

## 6. 飞鼠按钮手操

先确认飞鼠对应的事件设备号：

```bash
ls -l /dev/input/by-id
```

找到类似 `event-mouse` 或 `event-kbd` 指向的 `eventX`，例如 `/dev/input/event4`。

启动飞鼠手操：

```bash
cd /home/raybot/raybot_chassis_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch chassis_move protocol_airmouse.launch.py \
  robot_base_url:=http://192.168.1.55:8283 \
  robot_id:=ubot-001 \
  input_event_path:=/dev/input/event4
```

默认按钮映射（可在参数 `button_bindings_json` 覆盖）：

- 上 / `W`：前进
- 下 / `S`：后退
- 左 / `A`：左移
- 右 / `D`：右移
- `Q` / 鼠标左键：左转
- `E` / 鼠标右键：右转
- `SPACE` / 鼠标中键：停止

## 7. 开机默认飞鼠控制（systemd）

可以。推荐用 `systemd` 把 `protocol_airmouse_bringup.launch.py` 设为开机自启。

1) 新建服务文件：

```bash
sudo tee /etc/systemd/system/raybot-airmouse.service >/dev/null <<'EOF'
[Unit]
Description=Raybot protocol airmouse bringup
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=raybot
WorkingDirectory=/home/raybot/raybot_chassis_ws
Environment=PYTHONUNBUFFERED=1
ExecStart=/bin/bash -lc 'source /opt/ros/humble/setup.bash && source /home/raybot/raybot_chassis_ws/install/setup.bash && ros2 launch chassis_move protocol_airmouse_bringup.launch.py input_event_path:=/dev/input/event4'
Restart=always
RestartSec=2

[Install]
WantedBy=multi-user.target
EOF
```

2) 启用并立即启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now raybot-airmouse.service
```

3) 查看状态与日志：

```bash
systemctl status raybot-airmouse.service
journalctl -u raybot-airmouse.service -f
```

说明：

- `input_event_path` 要替换成现场飞鼠真实设备号。
- 若日志报无权限读取 `/dev/input/eventX`，给运行用户补充 `input` 组权限或加 udev 规则。
- 如需保留手动启动方式，可继续使用 `protocol_bringup.launch.py` + `protocol_airmouse.launch.py` 分开启动。

## 8. 常见排查

`Package 'chassis_move' not found`：

```bash
cd /home/raybot/raybot_chassis_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
```

控制发错地址导致 `404 unsupported path /mission`：

- 控制命令必须发到机器人 `192.168.1.55:8283`
- 香橙派 `192.168.1.25:8283` 只负责接收回调

`MANUAL` 模式下任务不执行：

- 先切到 `AUTOMATIC`

`Waiting for at least 1 matching subscription(s)...` 一直不结束：

- 说明 `/chassis/command` 当前没有匹配订阅者
- 先确认 `/protocol_command_bridge` 是否在运行
- 再确认 `ros2 topic info /chassis/command -v` 中确实有 subscriber

`ros2 topic info /chassis/command -v` 提示 `Unknown topic '/chassis/command'`：

- 说明桥接节点没有创建这个订阅
- 常见原因是桥接节点没启动，或者当前终端没有加载正确工作区环境
