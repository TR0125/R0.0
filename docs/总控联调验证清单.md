# 总控联调验证清单

> 状态：`archive`
> 
> 主入口请优先使用：`联调与验收.md`。

本文用于验证总控通过统一入口 topic `/chassis/command` 控制底盘是否成功。

当前推荐接口：

- `/chassis/command`：`raybot_chassis_msgs/msg/ChassisCommand`
- `/chassis/command_legacy`：`std_msgs/String`，用于兼容旧 JSON 发布端

## 1. 启动节点

### 1.1 启动协议回调网关

```bash
cd /home/raybot/raybot_chassis_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch chassis_move protocol_bringup.launch.py
```

### 1.2 启动统一命令桥接节点

```bash
cd /home/raybot/raybot_chassis_ws
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch chassis_move protocol_command_bridge.launch.py
```

当前 launch 默认使用现场参数：

- `robot_base_url=http://192.168.1.55:8283`
- `robot_id=ubot-001`
- `legacy_command_topic=/chassis/command_legacy`

如果后续机器人地址变化，也可以在启动时覆盖：

```bash
ros2 launch chassis_move protocol_command_bridge.launch.py \
  robot_base_url:=http://192.168.1.55:8283 \
  robot_id:=ubot-002
```

统一命令桥接节点会为 mission 型命令自动补齐默认任务标识：

- `mission_name`：语义化名称，例如 `GotoGoalA`
- `mission_id`：递增实例号，例如 `goto-a-001`、`goto-a-002`

说明：

- 同一次任务的 `STARTING`、`RUNNING`、`SUCCEED` 会共用同一个 `mission_id`
- 同一种任务再次下发时，会生成新的递增 `mission_id`
- 如果总控显式传入 `mission_name` 或 `mission_id`，桥接节点优先使用总控给定的值

示例：

- 第一次 `GOTO_GOAL A`：`mission_name=GotoGoalA`，`mission_id=goto-a-001`
- 第二次 `GOTO_GOAL A`：`mission_name=GotoGoalA`，`mission_id=goto-a-002`
- 第一次 `PATROL_GOALS B->A`：`mission_name=PatrolBToA`，`mission_id=patrol-b-to-a-001`

说明：

- 这套命名规则只适用于 `/chassis/command` 桥接节点
- 如果改用 `protocol_cli` 直接下发任务，默认任务名仍是 `ManualMove`、`ManualHead`、`ManualGotoGoal`

### 1.3 可选：使用本地总控包发命令

```bash
ros2 run raybot_chassis_master chassis_master_cli -- goto-goal --goal A
```

## 2. 打开观察窗口

```bash
ros2 topic echo /chassis/command_result
```

```bash

```

```bash
ros2 topic echo /protocol/task_state --full-length
```

```bash
ros2 topic echo /protocol/robot_status --full-length
```

## 3. 联调步骤

### 3.1 切换到底盘可执行任务模式

```bash
ros2 topic pub --once /chassis/command raybot_chassis_msgs/msg/ChassisCommand \
  "{command_type: SET_MODE, operation_mode: SEMIAUTOMATIC}"
```

通过标准：

- `/chassis/command_result` 中出现 `ok=true`
- `protocol_command_bridge` 节点无报错

### 3.2 验证前进

```bash
ros2 run raybot_chassis_master chassis_master_cli -- \
  move --distance-mm 300 --speed-mm-s 150
```

通过标准：

- `/chassis/command_result` 中出现 `ok=true`
- `/protocol/mission_state` 中出现新的 `mission_id`
- `/protocol/task_state` 中出现 `cmd=move`
- `/protocol/robot_status` 中位姿前向变化
- 现场观察到底盘前进

### 3.3 验证旋转

```bash
ros2 run raybot_chassis_master chassis_master_cli -- \
  rotate --angle-deg 20 --speed-deg-s 40
```

通过标准：

- `/chassis/command_result` 中出现 `ok=true`
- `/protocol/mission_state` 中出现新的 `mission_id`
- `/protocol/task_state` 中出现 `cmd=head`
- `/protocol/robot_status` 中朝向角变化
- 现场观察到底盘左转

### 3.4 验证停止

```bash
ros2 topic pub --once /chassis/command raybot_chassis_msgs/msg/ChassisCommand \
  "{command_type: STOP}"
```

通过标准：

- `/chassis/command_result` 中出现 `ok=true`
- 机器人停止当前动作

### 3.5 验证导航到目标点

发命令前，先确认机器人地图中存在目标点 `A`。

```bash
ros2 run raybot_chassis_master chassis_master_cli -- goto-goal --goal A
```

通过标准：

- `/chassis/command_result` 中出现 `ok=true`
- `/protocol/mission_state` 中出现新的 `mission_id`
- `/protocol/task_state` 中出现 `cmd=goto`
- `/protocol/robot_status` 中位姿持续变化
- 现场观察到底盘到达目标点附近

### 3.6 验证回家

发命令前，先确认机器人地图中存在目标点 `Home`。

```bash
ros2 topic pub --once /chassis/command raybot_chassis_msgs/msg/ChassisCommand \
  "{command_type: GO_HOME}"
```

通过标准：

- `/chassis/command_result` 中出现 `ok=true`
- `/protocol/mission_state` 中出现新的 `mission_id`
- `/protocol/task_state` 中出现 `cmd=goto`
- 现场观察到底盘返回 `Home`

### 3.7 验证 AB 点往返

```bash
ros2 run raybot_chassis_master chassis_master_cli -- \
  patrol-goals --from-goal B --to-goal A --wait-at-goal-sec 10
```

通过标准：

- `/chassis/command_result` 中出现 `ok=true`
- `/protocol/mission_state` 中出现新的 `mission_id`
- `/protocol/task_state` 中依次出现 `cmd=goto`、`cmd=wait`、`cmd=goto`
- 现场观察到底盘执行 `B -> A -> 等待 -> B`

## 4. 最终成功判定

一条控制命令要判定为验证成功，建议同时满足以下条件：

- `/chassis/command_result` 中 `ok=true`
- `/protocol/mission_state` 中对应任务已启动
- `/protocol/task_state` 中对应子任务已执行
- `/protocol/robot_status` 中状态变化符合预期
- 现场机器人动作正确

说明：

- 仅 `command_result` 成功，只能说明桥接节点收到了命令并成功调用 HTTP 接口
- 真正的执行结果，仍需结合 mission、task、status 以及现场运动现象一起判断

## 5. 常见问题排查

### 5.1 `/chassis/command_result` 中 `ok=false`

说明桥接层处理失败，常见原因：

- JSON 格式错误
- `command_type` 不支持
- 缺少必填字段
- 机器人 HTTP 地址不可达

### 5.2 `ok=true` 但看不到 `/protocol/mission_state`

说明桥接层请求成功，但机器人没有正常回调任务状态，重点检查：

- `protocol_bringup` 是否正常启动
- 回调 IP 和端口是否填写正确
- 机器人是否能访问香橙派 `192.168.1.25:8283`

### 5.3 有任务状态但机器人不动

重点检查：

- 当前是否已切到 `SEMIAUTOMATIC`
- 目标点名称是否存在
- 机器人是否拒绝执行任务
- 底盘本体是否处于异常状态

### 5.4 `GOTO_GOAL` 或 `GO_HOME` 失败

重点检查：

- 地图中是否存在对应目标点
- 目标点名称大小写是否完全一致
- 当前地图是否为正确地图
