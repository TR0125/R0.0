# Raybot Chassis 对外接口文档

状态：`active`（导航见 `README.md`）

## 1. 文档说明

本文档用于说明 `raybot_chassis_ws` 当前可用的对外接口，面向以下读者：

- 调度/总控系统开发人员
- 现场联调与运维人员
- 协议对接与测试人员

当前实现以 **HTTP/JSON 协议** 为主，结合 **ROS 2 Topic 桥接**。未发现 WebSocket、MQTT、原生 TCP/UDP、ROS Service/Action 作为对外接口。

---

## 2. 系统角色与通信拓扑

- 机器人本体：接收控制命令（默认 `192.168.1.55:8283`）
- 香橙派网关：接收机器人状态回调并转发到 ROS（默认 `192.168.1.25:8283`）
- 总控系统：通过 ROS Topic 下发命令并订阅状态

数据流：

1. 总控发布 `/chassis/command`（`ChassisCommand`）
2. 命令桥接节点将其转换为 HTTP 请求，发送到机器人
3. 机器人通过 HTTP 回调上报状态到香橙派
4. 网关节点将回调原文转发到 `/protocol/*` Topic

## 4. HTTP 控制接口（香橙派 -> 机器人）

统一约定：

- `Content-Type: application/json`
- 响应 `code == 0` 表示成功
- 空响应按成功处理（本地封装为 `{"code":0}`）

### 4.1 接口清单

| 名称 | 方法与路径 | 关键请求字段 | 关键响应字段 |
| --- | --- | --- | --- |
| 模式切换 | `POST /robot/mode` | `robot_id`, `operation_mode` | `code` |
| 急停 | `POST /command/stop` | `robot_id` | `code` |
| 状态请求 | `POST /command/status` | `robot_id`, `report_type`, 可选 `report_duration` | `code` |
| 下发任务 | `POST /mission` | `mission_id`, `mission_name`, `mission_type`, `content_type`, `full_content` | `code` |
| 取消任务 | `POST /mission/cancel` | `mission_id`, `mission_name`, `mission_type`, `command=cancel` | `code` |

### 4.2 `operation_mode` 取值与使用建议

- `AUTOMATIC`
- `SEMIAUTOMATIC`
- `MANUAL`
- `SERVICE`

推荐：

- 标准调度运行使用 `AUTOMATIC`（上层统一下发任务，机器人自主执行）
- `SEMIAUTOMATIC` 仅用于人工半接管或恢复场景

补充：

- 协议状态字段中可能出现 `TEST`
- 当前本地 `set-mode` 常规联调链路不以 `TEST` 为目标模式

### 4.3 `report_type` 取值

- `battery`
- `shape`
- `path`
- `device`

说明：ROS 命令字段 `report_duration_sec` 在发送 HTTP 时映射为 `report_duration`。

### 4.4 Mission 子任务（`full_content[]`）

| `cmd` 类型 | 关键字段 |
| --- | --- |
| `move` | `task_id`, `distance`(mm), `speed`(mm/s), 可选 `time` |
| `head` | `task_id`, `angle`(deg), `speed`(deg/s), 可选 `angle_acc` |
| `goto`（pose） | `task_id`, `target=pose`, `x`, `y`, `th`, 可选 `time` |
| `goto`（goal） | `task_id`, `target=goal`, `goal`, 可选 `time` |
| `wait` | `task_id`, `time` |
| `charge` | `task_id`, `goal`（`auto` 或命名充电点） |

## 5. HTTP 回调接口（机器人 -> 香橙派）

网关监听：`http://<service_host>:<service_port>`，默认 `http://192.168.1.25:8283`。

### 5.1 基础接口

| 名称 | 方法与路径 | 说明 |
| --- | --- | --- |
| 健康检查 | `GET /health` | 服务在线检查 |
| 上线 | `POST /robot/online` | 机器人上线通知 |
| 下线 | `POST /robot/offline` | 机器人下线通知 |
| 登录 | `POST /robot/login` | 机器人登录通知 |
| 登出 | `POST /robot/logout` | 机器人登出通知 |

说明：`/robot/online` 与 `/robot/login` 的响应会回传回调地址配置（`register_endpoint`、`mission_endpoint`、`status_endpoints`、`command_endpoint`、`map_endpoint`）。

### 5.2 状态与信息回调

| 方法与路径 | 主要字段（示例） |
| --- | --- |
| `POST /robot/status` | `status_msg`, `pose_msg`, `speed_msg`, `mission_msg` |
| `POST /robot/mission/state` | `mission_id`, `mission_state` |
| `POST /robot/mission/task/state` | `task_id`, `task_cmd`, `task_state` |
| `POST /robot/info/battery` | `battery_msg` |
| `POST /robot/info/shape` | `shape` 相关 |
| `POST /robot/info/path` | 路径相关 |
| `POST /robot/info/sensor` | 传感器相关 |
| `POST /robot/alarm` | `device`, `code`, `level`, `error_msg`, `error_handling` |
| `POST /robot/map` | `map_msg` |

### 5.3 错误处理

- 路径不存在：`{"code":1002,"message":"not found"}`
- JSON 非法：`{"code":1002,"message":"invalid json"}`

### 5.4 状态判据关键字段（推荐上层直接消费）

`/robot/status` 里的 `status_msg` 推荐重点关注：

| 字段 | 类型 | 建议用途 |
| --- | --- | --- |
| `lost` | boolean | 定位是否丢失（“迷路”主判据） |
| `lost_reason` | string | 定位丢失原因 |
| `stuck` | boolean | 是否卡住 |
| `stuck_reason` | string | 卡住原因 |
| `estop` | boolean | 是否急停 |
| `work_status` | string | 当前工作状态 |
| `operation_mode` | string | 当前运行模式 |

建议将 `/protocol/robot_status` 与 `/protocol/mission_state`、`/protocol/task_state`、`/protocol/robot_alarm` 联合判定。

## 6. ROS 2 对外桥接接口（总控集成入口）

### 6.1 命令输入

| Topic | 类型 | 方向 | 说明 |
| --- | --- | --- | --- |
| `/chassis/command` | `raybot_chassis_msgs/msg/ChassisCommand` | 订阅 | 主命令入口 |
| `/chassis/command_legacy` | `std_msgs/String`（JSON） | 订阅 | 兼容旧格式入口 |

### 6.2 命令结果输出

| Topic | 类型 | 说明 |
| --- | --- | --- |
| `/chassis/command_result` | `std_msgs/String`（JSON） | 执行结果（`ok`, `command_type`, `request`, `response`, `error`） |

### 6.3 状态输出（网关透传）

| Topic | 对应回调 |
| --- | --- |
| `/protocol/robot_status` | `/robot/status` |
| `/protocol/mission_state` | `/robot/mission/state` |
| `/protocol/task_state` | `/robot/mission/task/state` |
| `/protocol/robot_alarm` | `/robot/alarm` |
| `/protocol/robot_battery` | `/robot/info/battery` |
| `/protocol/robot_shape` | `/robot/info/shape` |
| `/protocol/robot_path` | `/robot/info/path` |
| `/protocol/robot_sensor` | `/robot/info/sensor` |
| `/protocol/robot_map` | `/robot/map` |
| `/protocol/robot_online` | `/robot/online` |
| `/protocol/robot_offline` | `/robot/offline` |
| `/protocol/robot_login` | `/robot/login` |
| `/protocol/robot_logout` | `/robot/logout` |

所有上述 Topic 消息类型均为 `std_msgs/String`，`data` 内为协议原始 JSON 文本。

字段约定：

- `/protocol/task_state` 里字段应使用 `task_cmd`（不是 `cmd`）
- 网关只做透传，不改写协议 JSON 字段名

### 6.4 位姿标准化输出

为便于导航、可视化和上层状态融合，系统新增 `robot_status -> PoseStamped` 桥接：

| Topic | 类型 | 来源 | 说明 |
| --- | --- | --- | --- |
| `/raybot/base_pose` | `geometry_msgs/PoseStamped` | `/protocol/robot_status` 的 `pose_msg` | 将协议位姿标准化为 ROS 位姿 |

字段映射：

- `pose_msg.px`（mm） -> `pose.pose.position.x`（m）
- `pose_msg.py`（mm） -> `pose.pose.position.y`（m）
- `pose_msg.pt`（deg，默认） -> 四元数 `z/w`
- `pose.header.frame_id = parent_frame`（默认 `world`）

超时策略：

- 当 `pose_timeout_sec` 内未收到新位姿，节点停止发布并打印告警日志，避免上层消费陈旧位姿。

## 7. `command_type` 与 HTTP 映射

| `command_type` | 关键字段 | 目标 HTTP |
| --- | --- | --- |
| `SET_MODE` | `operation_mode` | `POST /robot/mode` |
| `STOP` | - | `POST /command/stop` |
| `MOVE` | `distance_mm`, `speed_mm_s`, 可选 `time_sec` | `POST /mission`（`move`） |
| `ROTATE` | `angle_deg`, `speed_deg_s`, 可选 `angle_acc_deg_s2` | `POST /mission`（`head`） |
| `GOTO_POSE` | `x_mm`, `y_mm`, `heading_deg`, 可选 `time_sec` | `POST /mission`（`goto pose`） |
| `GOTO_GOAL` | `goal`, 可选 `time_sec` | `POST /mission`（`goto goal`） |
| `GO_HOME` | 可选 `goal`（默认 `Home`） | `POST /mission`（`goto goal`） |
| `CHARGE` | 可选 `goal`（默认 `auto`） | `POST /mission`（`charge`） |
| `PATROL_GOALS` | `from_goal`, `to_goal`, `wait_at_goal_sec`, 可选 `goto_time_sec` | `POST /mission`（多任务组合） |
| `REQUEST_STATUS` | `report_type`, 可选 `report_duration_sec` | `POST /command/status` |
| `CANCEL_MISSION` | `mission_id`, `mission_name`, 可选 `mission_type` | `POST /mission/cancel` |

说明：mission 型命令会自动补齐 `mission_id` 与 `mission_name`（若未显式提供）。

## 8. 快速联调建议

1. 确认网络互通：
   - 香橙派可访问机器人 `192.168.1.55:8283`
   - 机器人可回调香橙派 `192.168.1.25:8283`
2. 启动网关：`ros2 launch chassis_move protocol_bringup.launch.py`
3. 启动命令桥：`ros2 launch chassis_move protocol_command_bridge.launch.py`
4. 启动位姿桥：`ros2 launch chassis_move robot_status_pose_bridge.launch.py`
5. 发布一次 `SET_MODE` + `REQUEST_STATUS` 验证链路
6. 通过 `/chassis/command_result` 与 `/protocol/robot_status` 双向确认请求闭环
7. 订阅 `/raybot/base_pose`，确认坐标持续更新且单位为米
8. 验证 `/protocol/task_state` 时使用 `task_cmd` 字段做判断

## 9. 已知约束与注意事项

- 当前控制模型为任务型控制，不提供 `/cmd_vel` 持续速度接口。
- 对外主入口建议使用 `/chassis/command`，`/chassis/command_legacy` 仅用于兼容场景。
- `task_state` 回调字段使用 `task_cmd`，不要误写为 `cmd`。
- `base_pose` 来自 `/protocol/robot_status` 桥接，默认 mm->m 且 yaw 按角度处理。
- 调度常态模式建议定义为 `AUTOMATIC`，`SEMIAUTOMATIC` 用于半接管场景。
- 详细字段全集与权威定义以《调度系统与机器人通信协议》PDF 为准。
