## 1. 总体结构

当前包保留的是协议任务控制路线：

```text
控制侧:
  raybot_chassis_master
    -> /chassis/command (ChassisCommand)
    -> protocol_command_bridge
    -> protocol_actions
    -> protocol_client
    -> robot controller (192.168.1.55:8283)

  protocol_cli / protocol_teleop
    -> protocol_actions
    -> protocol_client
    -> robot controller (192.168.1.55:8283)

回调侧:
  robot callbacks
    -> protocol_gateway
    -> /protocol/*
```

## 3. 关键数据流

### 3.1 CLI / 手操

```text
protocol_cli / protocol_teleop
  -> protocol_actions
  -> ProtocolHttpClient
  -> robot controller
```

这些入口都直接面向机器人本体 HTTP 服务地址 `192.168.1.55:8283`。

### 3.2 总控单 Topic 桥接

```text
/chassis/command
  -> ProtocolCommandBridgeNode
  -> dispatch_protocol_command
  -> protocol_actions
  -> robot controller
```

这条路线的关键点：

- 总控优先发布 `ChassisCommand`
- legacy `std_msgs/String` 兼容入口保留在 `/chassis/command_legacy`
- 桥接节点按 `command_type` 分发
- mission 型命令自动补齐默认 `mission_name` 和递增 `mission_id`

### 3.3 回调网关

```text
robot callbacks
  -> ProtocolGatewayNode
  -> /protocol/robot_status
  -> /protocol/mission_state
  -> /protocol/task_state
```

这条路线的关键点：

- 香橙派监听 `192.168.1.25:8283`
- 机器人把回调推到香橙派
- 网关不代理控制接口

## 4. 关键职责

### 4.1 `ProtocolHttpClient`

职责：

- 统一 JSON POST
- 统一响应解析
- 统一 HTTP 错误处理

### 4.2 `protocol_mission`

职责：

- 构造 `move/head/wait/goto/charge`
- 组装完整 mission
- 补齐顺序 `task_id`

### 4.3 `protocol_actions`

职责：

- 封装协议动作
- 供 CLI、桥接节点、手操节点复用

### 4.4 `ProtocolCommandBridgeNode`

职责：

- 接收 `/chassis/command`
- 解析 `ChassisCommand`
- 兼容解析 `/chassis/command_legacy` 的 JSON
- 生成默认任务标识
- 转发结果到 `/chassis/command_result`

### 4.5 `ProtocolGatewayNode`

职责：

- 接收机器人回调
- 回复机器人回调地址配置
- 转发 ROS topic

## 5. 当前边界

- 不提供实时 `cmd_vel`
- 不提供暂停/恢复
- 横移依赖 `goto pose`
