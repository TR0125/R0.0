# 底盘上电启动说明

> 记录时间：2026-06-12  
> 说明：本文档整理底盘上电后各侧会启动的服务与节点，便于现场排查与验收。

---

## 整体架构

```text
飞鼠 → 香橙派(192.168.1.25) → HTTP → 底盘控制器(192.168.1.55:8283)
                ↑
        底盘状态回调 ← HTTP ← 底盘控制器
```

控制命令由香橙派发往底盘；底盘状态通过 HTTP 回调推送到香橙派。

---

## 1. 底盘本体上电（192.168.1.55）

底盘控制器上电后，会启动 **厂商调度协议 HTTP 服务**，默认地址：

- `http://192.168.1.55:8283`

该服务负责：

- 接收控制命令（`move` / `head` / `goto` / `stop` 等）
- 向香橙派推送状态回调

这部分属于底盘固件/厂商软件，**不在 `raybot_chassis_ws` 仓库内**；本仓库仅通过 HTTP 与之通信。

香橙派侧的启动脚本会 **等待底盘 HTTP 服务可达** 后再继续，逻辑见 `scripts/raybot-airmouse-start.sh` 中的 `wait_for_chassis()`。

---

## 2. 香橙派开机自启（与底盘控制相关）

当前已启用的 systemd 服务：

| 服务 | 状态 | 作用 |
|------|------|------|
| `raybot-airmouse.service` | **enabled** | 底盘飞鼠控制链路开机自启 |

服务文件路径：`/etc/systemd/system/raybot-airmouse.service`

主要配置：

```ini
[Unit]
Description=Raybot protocol airmouse bringup
After=network-online.target local-fs.target
Wants=network-online.target

[Service]
Type=simple
User=raybot
WorkingDirectory=/home/raybot/raybot_chassis_ws
Environment=PYTHONUNBUFFERED=1
Environment=ROS_DOMAIN_ID=11
ExecStart=/home/raybot/raybot_chassis_ws/scripts/raybot-airmouse-start.sh
Restart=always
RestartSec=5
TimeoutStartSec=600

[Install]
WantedBy=multi-user.target
```

---

## 3. `raybot-airmouse-start.sh` 启动流程

上电/开机后，该脚本依次执行：

1. **后台循环**：每 30 秒通过 HTTP 将底盘保持在 `AUTOMATIC` 模式（使用 `curl`，不再反复启动 `ros2 run`）
2. **等待飞鼠设备**：路径可通过环境变量 `RAYBOT_AIRMOUSE_EVENT_PATH` 覆盖；默认  
   `/dev/input/by-id/usb-XING_WEI_2.4G_USB_USB_Composite_Device-if02-event-kbd`
3. **等待底盘就绪**：`http://192.168.1.55:8283` 可访问（最长等待 300 秒）
4. **设置 AUTOMATIC 模式**
5. **请求路径状态上报**：`request-status path`，默认持续 300 秒（供飞鼠侧移使用）
6. **启动 ROS2 launch**：`protocol_airmouse_bringup.launch.py`

关键参数（可用环境变量覆盖）：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `RAYBOT_BASE_URL` | `http://192.168.1.55:8283` | 底盘 HTTP 地址 |
| `RAYBOT_ROBOT_ID` | `ubot-001` | 机器人 ID |
| `RAYBOT_AIRMOUSE_EVENT_PATH` | 见上文 by-id 路径 | 飞鼠 input 设备 |
| `RAYBOT_MAX_WAIT_SEC` | `300` | 等待设备/底盘/切模式的最长时间 |
| `RAYBOT_STATUS_REPORT_DURATION_SEC` | `300` | 路径状态上报时长 |
| `RAYBOT_MODE_REFRESH_INTERVAL_SEC` | `30` | 后台刷新 AUTOMATIC 的间隔 |

---

## 4. 最终拉起的 ROS 节点

由 `protocol_airmouse_bringup.launch.py` 启动以下 **2 个节点**：

| 节点 | 功能 |
|------|------|
| `protocol_gateway` | 在香橙派 `192.168.1.25:8283` 监听 HTTP 回调，转发到 `/protocol/robot_status` 等话题 |
| `protocol_airmouse` | 读取飞鼠按键，通过 HTTP 向底盘发送 move/head/stop 等命令；**左右平移**时直接读取 `/protocol/robot_status` 里的 `pose_msg`（`px`/`py`/`pt`） |

说明：飞鼠开机自启**不发布** `/raybot/base_pose`，左右平移也**不订阅**该话题。若总控或联调需要 `PoseStamped` 位姿，请手动启动 `robot_status_pose_bridge.launch.py`。

Launch 文件路径：

- `src/chassis_move/launch/protocol_airmouse_bringup.launch.py`

---

## 5. 上电后不会自动启动的底盘相关服务

按 `部署与启动.md`，以下服务需要 **手动启动**，当前未配置开机自启：

| 服务 / Launch | 作用 |
|---------------|------|
| `protocol_command_bridge.launch.py` | 总控 Topic → 底盘 HTTP 桥接 |
| 单独的 `protocol_bringup.launch.py` | 仅启动网关与位姿桥接（不含飞鼠） |
| `raybot_chassis_master` | 总控命令发布入口 |

如需完整总控链路，请参考 `部署与启动.md` 中的多终端启动步骤。

---

## 6. 推荐上电顺序

1. 路由器上电
2. **底盘上电** → 底盘 HTTP 服务启动
3. 香橙派上电 → `raybot-airmouse.service` 自动运行
4. 等待约 **20~40 秒**
5. 飞鼠可直接控制底盘，无需 SSH 手动启动节点

## 7. 验收命令

```bash
# 检查服务是否已设为开机自启
systemctl is-enabled raybot-airmouse.service
# 期望输出: enabled

# 检查服务当前是否运行
systemctl is-active raybot-airmouse.service
# 期望输出: active

# 查看服务状态
systemctl status raybot-airmouse.service

# 实时查看日志
journalctl -u raybot-airmouse.service -f
```

确认 ROS 节点是否在跑：

```bash
source /opt/ros/humble/setup.bash
source /home/raybot/raybot_chassis_ws/install/setup.bash
ros2 node list | grep -E 'protocol_gateway|protocol_airmouse'
```

## 9. 总结

| 位置 | 上电后启动内容 |
|------|----------------|
| 底盘本体 (192.168.1.55) | 厂商 HTTP 控制服务（8283 端口） |
| 香橙派 | `raybot-airmouse.service` → 网关 + 飞鼠控制（含切 AUTOMATIC、请求状态上报） |
| 未自启 | `protocol_command_bridge`、单独 `protocol_bringup`、`robot_status_pose_bridge`、总控发布 |

底盘上电后会启动自身的 **8283 HTTP 控制服务**；香橙派侧通过 **`raybot-airmouse.service`** 自动拉起网关和飞鼠控制两个节点，并在底盘就绪后将其设为 `AUTOMATIC` 模式、请求路径状态上报。
